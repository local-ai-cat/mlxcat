Before you quote any of this

Competitors were measured once, on 2026-08-21 and 08-22, and have not moved since. Every engine here improves over time. A stale rival line flatters us, and the fix is to re-measure them.

The machine drifts. An unchanged gpt-oss configuration measured 9.8% slower in the latest pass than the one before — same code, same host. Treat single-digit-percent moves as weather.

Peak memory is per process, not per cell. One server process serves every tier of a model, so a cell measured after a 16k tier inherits that tier's high-water mark.

gemma is serialized on purpose. Its batched decode left every row but the first unrotated — an MLX RoPE bug (KNOWN-FAILURES §1f) — so its concurrency numbers here are what correctness costs, not what the engine can do.
